# W01 閱讀連續性稽核

## 目的

把 `the-llm-editorial` 已驗證的寫作機制移植到數位插畫課程：先讓學生看到具體物件與視覺問題，再讓每一段正文回答上一段留下的問題，最後把輸出接到下一次實驗。

## 審查範圍

- 頁面：`src/pages/weeks/1.astro`
- 主要資料：`src/data/design-education.ts` 的 W01 觀察說明
- 閱讀段落：用 `data-reading` 標記的 10 段正文
- 視窗：相鄰兩段，共 9 個
- 排除：標題、卡片標籤、圖說、導覽、清單與裝飾圖

## 兩段視窗結果

`bun run check:reading-windows` 通過：9 個視窗通過，0 個連續性 finding，0 個可見 `ELI5` 標籤。

每個視窗依 skill 要求分成兩個獨立問題：

- **Forward**：上段留下什麼問題、下一個視覺操作或選擇理由？下段是否真的接著處理？
- **Backward**：下段需要哪些物件、術語、變數、輸出與因果關係？上段是否已提供？

## 已整合的修補

| 位置 | 讀者原本可能卡住的地方 | 修補 |
| --- | --- | --- |
| 首屏問題 → 第一週行動 | 「一張圖或一套作品」沒有立即接到怎麼開始 | 用「答案先從一個每天看得到的物件開始」接到觀察。 |
| 物件 → 椅子案例 | 椅子像突然換來的新例子 | 明說「先用一張椅子來看」。 |
| 觀察理由 → 合授分工 | 選圖理由和兩位老師的分工斷開 | 說明觀察表會成為後面課程交接的起點。 |
| 觀察方法 → W01 實驗 | `ELI5` 標籤代替了說明 | 移除可見標籤，直接寫椅子的輪廓、比例、材料與使用位置。 |
| 本週紀錄 → 下一週 | 作業檔案沒有接到後續工作 | 明說下一週從這些文字開始，先看留下的資料，再決定改哪裡。 |

## Anti-AI 審查

- [x] 移除可見的 `ELI5：` 前綴；ELI5 作為寫法，不作為學生要背的標籤。
- [x] 把抽象的「風格」「好看」拉回輪廓、比例、材質、使用方式與畫面位置。
- [x] 明確寫出學生、工具、老師與下一週分別做什麼。
- [x] 沒有用提示詞或工具名稱代替視覺判斷。
- [x] 保留失敗與下一個問題的紀錄位置，讓作業能接到下一輪。

## 三個角色的判定

### 目標學生

從椅子開始即可執行；不需要先懂風格術語。學生能指出畫面上的特徵，也知道要把哪一份紀錄留下來。

### 技術與製作審查

資料仍由 `src/data` 管理，頁面只負責組織和呈現。`data-reading` 只標示閱讀順序，不把可見課程 copy 藏進 layout 元件。圖說與正文仍分開。

### 發展編輯

W01 的順序是：具體問題 → 物件觀察 → 選擇理由 → 合授交接 → 單一觀察實驗 → 檔案交付 → 下一個問題。每段都留下下一段可以承接的物件或動作。

## 驗收邊界

靜態閱讀稽核只確認標記段落的相鄰關係，不能代替完整人工 forward / backward 閱讀、圖片可讀性、工具條款與授權核對。網站交付仍需執行 `bun run typecheck` 與 `bun run build`。

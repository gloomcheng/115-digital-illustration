# 第 16 週查核：交接包的驗收條件

查核日期：2026-11-04

## 1. 20 分鐘是怎麼來的

| 項目 | 秒 | 分類 |
| --- | --- | --- |
| 下載四個模型檔 | 280 | 實測（第 09 週，免費版 T4） |
| 生成第一頁 2 秒動態 | 619 | 實測（第 14 週，第 1 頁） |
| 合計 | 899（15.0 分鐘） | 推算 |
| 驗收上限 | 1200（20 分鐘） | 設想 |

留給匯入設定、找檔案、改檔名的時間是 5 分鐘。用第一頁的 619 秒而不是第二頁的 588 秒，因為換機器之後跑的是第一頁。這個上限是本課訂的驗收門檻，不是工具限制，頁面寫成「設想的 20 分鐘」，不寫成「正常應該 20 分鐘」。原來的 15 分鐘版本留不出操作時間，已改掉。

## 2. 設定檔裡有什麼、沒有什麼

工作流 JSON 存的是節點、連線與每個欄位的值。裡面沒有模型權重，也沒有 input 資料夾的圖。換一台機器匯入之後，缺模型的那幾格會標紅；這是第 12 週教過的同一種錯誤，屬於預期行為，不是交接失敗。頁面第 02 步寫明這一點，並把「紅框節點要對得上第 03 步的模型清單」當成檢查條件。

notebook 連結之所以放進交接包，理由是它負責下載模型與啟動後端，不是因為它會記住畫面。頁面第 05 步這樣寫，不用「所以」把兩件事接成因果。

## 3. 授權的主張與來源

- SDXL：CreativeML Open RAIL++-M，條文附使用限制。來源為 Hugging Face 上的 `stabilityai/stable-diffusion-xl-base-1.0` 授權檔，頁尾附連結與核對日期。
- Juggernaut XL v9：SDXL 的第三方微調模型（fine-tune），授權 CreativeML OpenRAIL-M。以 Hugging Face API 核對 `RunDiffusion/Juggernaut-XL-v9` 的 `cardData.license` 為 `creativeml-openrail-m`（2026-11-04）；檔名 `Juggernaut-XL_v9_RunDiffusionPhoto_v2.safetensors` 來自同一支 API 的檔案清單。頁面因此不寫「同一家族的不同版本」，而是寫「拿 SDXL 再訓練的微調模型」。
- Wan2.2：Apache 2.0，允許商用。來源為 ComfyUI 官方 Wan2.2 教學文件。
- 頁面要求學生自己填四欄（檔名、來源網址、授權名稱、不可做的事），而不是背一條結論。理由是同一門課會用到兩種授權。只記「可以商用」會漏掉 RAIL（Responsible AI License，負責任 AI 授權）附的使用限制。

## 4. 沒有涵蓋的

- 集體授權、字型授權、音樂授權：這一週只處理模型與工具，其餘屬期末提案的範圍。
- 模型再散布：頁面不談把權重傳給同學，只談「對方自己下載」。

## 5. 商業主線

交接包是這門課唯一一份「別人要用你的東西」的文件。頁面的驗收條件放在別人的機器上跑得出來，而不是檔案齊不齊：齊了但跑不出來，等於沒有交接。這也是接案與外包現場的實際門檻。

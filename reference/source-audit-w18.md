# 第 18 週查核：來源清單的欄位與範例

查核日期：2026-11-04

## 1. 範例那一列用什麼檔案

| 欄位 | 值 | 來源 |
| --- | --- | --- |
| 檔名 | `work-durer-rhinoceros.webp` | 本倉庫 `public/illustrations/`，第 02 週用的圖 |
| 來源網址 | `https://commons.wikimedia.org/wiki/File:Albrecht_D%C3%BCrer,_The_Rhinoceros,_1515,_NGA_47903.jpg` | Wikimedia Commons 檔案頁，2026-09-29 核對 |
| 授權名稱 | CC0（美國國家美術館藏本） | 同上檔案頁的授權欄 |
| 用途 | 第 02 週比較木刻線條；不放進成品 | 本課程第 02 週教材 |
| 查核日期 | 2026-09-29 | 加入 `src/data/historical-works.ts` 當天 |

選這一筆當範例的理由：它是這門課真的用過的圖，授權是 CC0，學生點進同一個頁面就能看到一樣的授權欄。範例本身可被驗證，不是為了排版編出來的。

木刻原作在公有領域，但照片與掃描檔另有權利人，所以欄位記的是「這一個檔案」的授權，不是「杜勒死了多久」。這一點在第 02 週已寫過，這一週再用同一筆紀錄示範一次。

## 2. 第二列是示意的

第二列（期末生成圖）不是真實檔案，頁面 `kind` 已標明「第二列是示意」。它示範兩件事：生成圖的來源欄填工具與條款頁，不填「AI 生成的」；授權欄填模型授權名稱，例如 CreativeML Open RAIL++-M。

## 3. 頁面主張的分類

| 頁面寫的 | 分類 |
| --- | --- |
| 授權要抄全名與版本（CC0 1.0、CC BY 4.0、CreativeML OpenRAIL-M） | 文件 |
| 條款會改版，所以要寫查核日期與下次再看日期 | 文件（各授權頁的版本欄位） |
| 來源網址要指到檔案頁，不是搜尋結果 | 教學設計 |
| 三份資料（官方、產業或學術、實作） | 教學設計，不是研究方法的規定 |

## 4. 被排除的說法

| 說法 | 排除理由 |
| --- | --- |
| 「CC0 就可以隨便用」 | CC0 只處理著作權，不處理肖像、商標與場館規定。頁面只要求抄授權名稱，不替學生判斷個案。 |
| 「AI 生成的圖沒有授權問題」 | 模型授權（RAIL 系列）附使用限制，工具條款另有一份。頁面要求兩者都記。 |
| 「免費方案做出來的東西不能賣」 | 免費與商用是兩件事：Colab 免費版限制的是執行方式，模型授權限制的是用途。頁面分開寫，不把兩者混成一句。 |

## 5. 與其他週的關係

- 第 16 週交的是交接包，這一週交的是交接包裡「來源」那一欄的完整版。
- 第 17 週查的是「誰付錢」，這一週查的是「我用的東西能不能這樣用」。兩題一起，才是作品能不能拿出去的完整答案。

## 6. 商業主線

第 07 步要求把素材標成免費、試用、付費，並寫出「要賣之前必須換掉什麼」。這一題沒有標準答案：換掉素材可能讓作品失去原本的樣子，不換就不能賣。頁面只要求寫出數量與那一行決定，不替學生選。

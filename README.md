# 數位插畫與動態繪本創作

靜宜大學 115 學年度第 1 學期的合授課程網站，給修課學生與路過的讀者。

線上看：https://gloomcheng.github.io/115-digital-illustration/

第一週你會拿一個身邊的物件開始，先說出自己看見了什麼，再把它變成可以比較的畫面。後面才接風格、工具、角色、場景、分鏡和動圖。每一次試做都留下原始版本、改動的位置和下一個問題，最後才知道作品是怎麼長出來的。

## 課程在做什麼

- 先把畫面放在一起比較，指出它讓人先看到什麼、漏掉什麼。
- 把風格拆成線條、形狀、色彩、材質、空間與用途。
- 拿同一個工作在不同工具裡跑一次，記下額度、格式和卡住的位置。
- 用提示詞與畫面說明反覆試做一個視覺方向。
- 將角色、場景與版面整理成別人接得下去的作品包。
- 從畫面要放在哪裡、誰會先看到、能不能延伸與素材來源檢查一個 IP。

## 誰帶哪一段

這門課兩位老師一起帶。AI 工具這一段教你挑工具、寫畫面說明、拆風格、快速試誤，最後整理成作品包；故事與分鏡那一段帶故事腳本、分鏡和鏡頭語言。網站每週標出誰帶，後半段你把分鏡條件轉成 AI 資產實驗。

## 這學期怎麼走

完整進度請看網站中的「課程進度」。從導航列進入課程進度、風格怎麼看、工具怎麼選、動圖怎麼做和作品怎麼交。

前 8 週先把畫面拆開來看，也習慣留下每次試錯。第 9–10 週接上故事、分鏡和鏡頭語言。第 11–16 週把分鏡轉成角色、場景和版面，最後整理成作品交接包。第 17–18 週再到展演和數位圖書館看看，作品離開課堂後會遇到什麼。

W04 起也可以加入一套不靠骰子決定的飲料店經營模擬，12 週跑 12 年，讓視覺與製作的選擇接回現金流、用人、需求和風險。

學生用方向鍵在自己的店裡走動，走到貨架、吧檯、門口、辦公室才會出現可執行的行動——移動本身是一種成本，所以三個決策格不是免費的。看得見的因果是這個模擬的重點：多請的人沒有工位，會以灰衣低頭的樣子站在櫃檯後面；空著的工位在檯面上畫一個叉；貨架空了會看見客人空手走掉，而「缺的是工位」和「缺的是貨」是兩個不同的畫面、也指向完全不同的解法。

進度寫進本機 SQLite，老師關掉筆電、隔週再開，學生輸入同一個房號和店名就回到原本的位置；每月選了什麼、預期什麼、實際發生什麼，永久留著當學生的經營紀錄。平時學生只看得到自己的店，每年只在年結算時公開一次名次與該年淨值變化。

```bash
bun run shop          # 開機頁 /（上課前按「開一屆新的」拿到房號）
bun run shop:check    # 規則 + 美術 + 場景驗算 47 項
bun run shop:e2e      # 三角色協作 39 項（需先開 shop）
bun run shop:persist  # 關機重開 25 項（自己開關伺服器）
bun run shop:rehearse # 跑完第 1 年，檢查三種玩法都不會卡住
bun run shop:sprites  # 重新產生像素精靈圖到 public/
bun run shop:preview  # 用客戶端那份座標畫出預覽圖，用眼睛看
bun run shop:chars    # 把每個角色影格放大 8 倍並畫上像素網格
```

美術是俯視 3/4 的像素圖，由 `scripts/shop-sim/make-sprites.py` 產生真的 PNG 進 `public/`，不依賴任何外部圖庫或生圖服務。`shop:preview` 會從 `scene.ts` 讀出座標重畫一次——預覽跟遊戲用的是同一份資料，不會有「預覽好看、遊戲走樣」的情況。

`shop:chars` 是改角色時一定要跑的那一支。像素美術的問題九成是比例和對比，機械驗算（寬度、色碼數、影格數）一個都擋不住：頭寬是不是比肩窄、眼睛下方有沒有留空白、走路影格的腳有沒有換位置——這些必須放大用眼睛看。它輸出三張圖：各種角色並排、走路影格並排、以及遊戲實際大小（1 倍與 3 倍）。

設計規格與校準邊界記在 [`reference/financial-simulation-design.md`](reference/financial-simulation-design.md)；其中的價格、成本和事件數字都是構造的課堂參數，不是市場統計。
